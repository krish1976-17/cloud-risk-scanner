CLOUDGUARD GUIDE

Clear results, careful decisions.

How to run a scan, understand the findings, and know what they can tell you.

⌕ Open scanner
Use this as a learning aid. CloudGuard checks a limited snapshot and can miss issues or report false positives. Confirm every finding in the real application or cloud account.
01 · Run a scan

Cloud configuration JSON

  1. Open the dashboard and choose Cloud config JSON.
  2. Paste or upload an array of resource objects with a supported type.
  3. Run the scan and review which configuration fields triggered each rule.

It analyzes the JSON you provide in your browser. It does not connect to AWS, Azure, or Google Cloud.

02 · Run a scan

Public website URL

  1. Choose Web application and enter a full public https:// or http:// address.
  2. Scan only a site you own or have permission to assess.
  3. Review the pages scanned and the findings below.

The scanner makes read-only GET requests, follows same-site links, and checks up to 12 pages. It does not log in, submit forms, or send attack payloads.

03 · Understand severity

What the labels mean

  • Critical / High: review promptly; a serious weakness may be exposed.
  • Medium: check whether the missing protection matters for this application.
  • Low: a hardening suggestion with a typically smaller direct impact.

Severity is a prioritization hint, not proof that a site is vulnerable. Repeated findings can appear on several pages.

04 · Understand the score

Score is an estimate

The dashboard starts at 100 and subtracts points for each finding. Repeated findings can lower it several times, so the score is not an industry-standard rating and should not be compared with another scanner.

Use the individual evidence and fixes to decide what to verify. A high score does not prove the application is safe.

05 · Make each finding easier to act on

Suggested improvements for clearer results

  • Show the evidence: name the page or resource and the exact response header or JSON field that triggered the rule.
  • Explain the impact: use one short sentence describing what could happen and when the risk matters.
  • Give a next step: put a concrete verification or fix directly beside the finding.
  • Label uncertainty: distinguish a confirmed missing setting from a heuristic that needs manual review.
  • Explain the score: show the deductions and let repeated findings be grouped so the user can see what changed the number.
06 · Know the limits

What CloudGuard does not scan

It does not inspect source code files or binaries, log in to websites, test authenticated pages, execute JavaScript like a full browser crawler, inspect business logic, or connect to a real cloud account. The website scan only observes public HTTP responses; the configuration scan only evaluates the JSON snapshot provided.

Use the results to guide a manual review, not as a penetration test or a security certification.
